Platform Documentation

The cNGN savings & lending ecosystem on Base

Pawasave lets Nigerians save in Naira, earn on-chain yield in cNGN, run Ajo circles, invest, and borrow against their assets — from a single mobile app. This documentation covers how the platform works and how partners integrate with it.

Overview

Pawasave is a consumer money app backed by an on-chain lending protocol, PawasaveLend. Users experience a familiar Naira wallet; behind the scenes, balances settle in cNGN (the regulated Naira stablecoin) on Base, Coinbase's Ethereum Layer-2. A closed-loop design means the consumer app continuously supplies liquidity to the lending pools that fund borrowing.

NetworkBase mainnet (Ethereum L2, chain ID 8453)
Unit of accountcNGN — Naira-pegged stablecoin (₦1 = 1 cNGN)
CustodyInstitutional multi-signature custody
Consumer statusLive at pawasave.xyz

Who it's for

  • Everyday savers & traders — save, run Ajo, invest and borrow in one place.
  • SMEs & merchants — working-capital credit at rates far below the informal 40–80%.
  • Fintech partners — tap PawasaveLend liquidity and cNGN rails through the partner API (preview).

Products

Four consumer products sit on one balance, so money moves between saving, investing and borrowing without friction.

Save Live

cNGN savings with automatic yield. P-AUTO routes locked balances to vetted yield and compounds continuously — users just see “Earn up to X%”.

Ajo Live

Digitised Esusu savings circles with automated contributions, scheduled payouts, and full transparency for every member.

Invest Live

Market exposure alongside savings, managed from the same wallet balance.

Borrow Live

Asset-backed cNGN loans against locked savings and holdings, with transparent interest and instant disbursement.

How value flows

  1. User funds the wallet with Naira (bank transfer / NUBAN) or crypto; it settles as cNGN.
  2. Locking savings supplies the P-AUTO vault and PawasaveLend liquidity pools.
  3. Borrowers post collateral and draw cNGN credit lines from those pools.
  4. Interest and reserve fees flow back to suppliers and platform revenue.

Security

Security is foundational. Pawasave completed an independent security review and remediated its findings, and applies defence-in-depth across its application, data and custody layers.

Independent audit

Reviewed by an external security team, with findings remediated ahead of launch.

Protected transactions

Money-moving actions require a private transaction PIN, with an optional biometric device lock.

Least-privilege data

Strict per-user data isolation, so a customer can only ever access their own records.

Multi-signature custody

On-chain assets are secured under multi-signature control; signing keys are never exposed to the application.

Compliance & KYC

Identity verification uses Sense biometric liveness. Sensitive identifiers are never stored in plain text, and only the minimum data needed for verification is retained.

  • Tiered access — verification is required before withdrawals; limits scale with KYC level.
  • Data minimisation — only what's needed for verification is retained; biometric checks are delegated to the provider.
  • Auditability — every balance-changing action is recorded and reconcilable on-chain.
Regulatory posture: Pawasave settles in the regulated cNGN stablecoin and is pursuing compliant institutional fiat-gateway integrations as part of its partnership roadmap.

Fees & Revenue

Revenue is protocol-native and transparent. The lending engine applies a reserve fee on interest; the consumer app applies clearly-disclosed product fees.

SourceWhat it is
Reserve feeA 10% share of borrow interest, retained by the protocol to build reserves and fund platform revenue.
Loan interestInterest accrued on outstanding cNGN loans, shared with liquidity suppliers.
Origination feeA one-off fee applied when a loan is disbursed.
Yield spreadA spread on returns from savings routed through the P-AUTO allocator.
Early-exit penaltyApplied when a user breaks a fixed savings goal ahead of term.

A specialised Kink interest-rate model raises borrow rates during hyper-utilisation, protecting liquidity and rewarding suppliers when demand is high.

Developers — Getting Started

Status: Early-access preview. The partner API is in active development. The endpoints, payloads and events below describe the target interface for fintechs integrating PawasaveLend liquidity and cNGN rails. They are not yet generally available — request sandbox access to build against them.

The partner API lets a fintech offer Pawasave-powered savings, deposits and cNGN credit to its own users — a backend liquidity layer for Nigerian stable finance.

Base URL (sandbox)https://sandbox.api.pawasave.xyz/v1
Base URL (production)https://api.pawasave.xyz/v1
FormatJSON over HTTPS; UTF-8; amounts in kobo (integer, ₦1 = 100)
VersioningPath-based (/v1); breaking changes ship under a new version

Authentication

Requests are authenticated with a secret API key sent as a bearer token. Keys are issued per environment; never expose a secret key in client-side code.

# Every request carries your secret key
curl https://sandbox.api.pawasave.xyz/v1/balances \
  -H "Authorization: Bearer sk_sandbox_..."
Webhook signing: outbound webhooks are signed with an X-Pawasave-Signature header (HMAC-SHA256 of the raw body using your webhook secret). Verify it before trusting a payload.

Endpoints

Representative resources for the partner integration. All amounts are integer kobo.

MethodPathDescription
POST/customersCreate a customer (KYC reference, contact).
POST/deposits/nubanIssue a per-customer NUBAN; funds settle as cNGN.
GET/balances/:customerIdFetch cNGN + savings balances.
POST/savings/lockLock a balance into the P-AUTO yield vault.
POST/loansOpen a collateral-backed cNGN loan.
GET/loans/:loanIdLoan status, balance, and repayment schedule.
POST/withdrawalsWithdraw cNGN to a bank account (off-ramp).

Example — open a loan

POST /v1/loans
{
  "customer_id": "cus_8fk21a",
  "principal_kobo": 5000000,        // ₦50,000
  "collateral": { "type": "locked_savings", "ref": "lock_2231" },
  "term_days": 30
}

Webhooks & Events

Pawasave delivers signed events to your endpoint as state changes. Respond 2xx within 5s; deliveries retry with backoff.

EventFires when
deposit.creditedAn inbound deposit settles to a customer's cNGN balance.
withdrawal.settledAn off-ramp withdrawal completes.
loan.disbursedA loan is opened and cNGN is disbursed.
loan.repaidA loan is fully repaid and collateral released.
loan.liquidatedCollateral is liquidated to cover an at-risk loan.
 
{
  "event": "deposit.credited",
  "data": {
    "customer_id": "cus_8fk21a",
    "amount_kobo": 2500000,
    "reference": "dep_a1b2c3",
    "settled_at": "2026-07-27T10:15:00Z"
  }
}

Errors & Rate Limits

Errors use standard HTTP status codes with a machine-readable body. Rate-limited requests return 429; back off and retry.

{
  "error": {
    "code": "insufficient_collateral",
    "message": "Collateral value is below the required threshold."
  }
}
StatusMeaning
400Invalid request — see error.message.
401Missing or invalid API key.
402Insufficient balance / collateral.
429Rate limit exceeded — retry with backoff.
5xxTransient server error — safe to retry idempotently.

  3. Build against the sandbox base URL; verify webhook signatures.
